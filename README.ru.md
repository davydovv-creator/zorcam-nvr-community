# Zorcam

[English](README.md) · **Русский**

Лёгкая система видеонаблюдения для Raspberry Pi 3: захват кадров с IP-камер по RTSP, детекция движения, онлайн-трансляция и веб-галерея с авторизацией. Одна камера или несколько. Работает на Debian 13 (Raspberry Pi OS), без Docker и внешних Python-зависимостей, кроме пакетов из apt. После `install.sh` всё настраивается в браузере: мастер спрашивает настройки, пользователей и камеры.

| | |
|---|---|
| Захват | постоянное RTSP-соединение с каждой камерой через go2rtc, только ключевые кадры (~2.5 кадра/сек); снимок для Timelapse раз в 5 сек («Периодичность снимков» камеры) |
| Реакция на движение | запись 10-секундного видео (H.264) с момента движения, push-уведомление с названием камеры |
| Галерея | порт 80: Live (все камеры, по 1, 2 или 3 в ряд; на экране ноутбука — 2, 3 или 4) / Записи: Timelapse и Видео (вкладка на каждую камеру: таймлапс снимков, ролики с движением), приложение для iPhone и широкий вид с боковой панелью для ноутбука |

## Live-трансляция

Вкладка Live открывается по умолчанию. Основной способ показа — WebRTC через [go2rtc](https://github.com/AlexxIT/go2rtc): полный поток камеры (все кадры, 25 fps) без перекодирования, задержка ~0.3–0.5 сек.

- Вкладка Live показывает все камеры, каждую под её названием, со своим плеером. Если камер несколько, кнопки над ними ставят по 1, 2 или 3 камеры в ряд (на широком экране — 2, 3 или 4); выбор хранится на устройстве (в браузере), так что на телефоне и компьютере он может быть разным. Плеер, у которого картинка не движется дольше ожидания WebRTC плюс 15 с (завис в «Буферизации», например после перехода телефона с Wi-Fi на LTE), переподключается сам, сначала по WebRTC; при смене сети переподключаются все плееры, а кнопка с круговой стрелкой над ними делает то же вручную (в приложении на iPhone жест «потянуть вниз» над плеером страницу не обновляет). go2rtc держит одно подключение к каждой камере: его постоянно читает детектор, плееры Live и HLS используют его же.
- Поворот и зум: у ONVIF-камеры с поворотным механизмом (PTZ) под плеером появляется раскрывающийся переключатель «Управление» (после каждой загрузки страницы свёрнут), а в нём — кнопки со стрелками и зумом (для `viewer` и `admin`, не для `liveviewer`; только для камер, включённых пользователю). Кнопку держат — камера движется, отпустили — остановилась; на ноутбуке — навести указатель на камеру с раскрытым управлением и нажимать стрелки и `+` / `-`. Точек обзора (пресетов) пока нет. Галерея говорит с камерой по ONVIF, под логином камеры и её паролем (теми же, что для RTSP), по «Адресу ONVIF» камеры (только адреса домашней сети): камера, найденная поиском ONVIF, запоминает адрес, с которого ответила, у добавленной вручную впишите поле «Адрес ONVIF», например `http://192.168.1.50:8000/onvif/device_service`. Запасного адреса нет: без него переключатель «Управление» под плеером неактивен. Некоторые камеры (например, Bootslab) пускают по ONVIF только отдельного пользователя ONVIF, созданного в настройках камеры: тогда укажите его логин и пароль у камеры в Zorcam. Каждая команда движения несёт таймаут 2 с, поэтому камера остановится сама, если «стоп» потерялся. Кнопок нет: у камеры нет PTZ, выключен ONVIF или отказал логин (`journalctl -u zorcam-nvr-gallery | grep ptz`).
- API go2rtc слушает только `127.0.0.1:1984`. Браузер обменивается SDP с go2rtc через галерею (`POST /live/webrtc`), поэтому действует её логин.
- Видео идёт от go2rtc к браузеру напрямую, через порт **8555 (TCP и UDP)**. Этот порт должен быть доступен из сети, где открыта галерея.
- RTSP-сервер go2rtc слушает только `127.0.0.1:8554` (из сети недоступен). Детектор и HLS берут поток камеры там, поэтому пароль камеры не попадает в командную строку ffmpeg, которую любой пользователь Pi видит через `ps`.
- Для Live в любом браузере камера должна отдавать H.264. H.265 go2rtc передаёт по WebRTC без перекодирования, и его показывает любой браузер на iPhone и iPad (все они на движке Safari) и Safari на Mac (iOS 18, macOS 15 и новее); Chrome и Firefox на Android и компьютере — не всегда.

Резервный способ — HLS. Если WebRTC не соединился за 8 сек (порт 8555 закрыт, браузер без WebRTC), плеер переключается на HLS. Галерея по запросу запускает ffmpeg, который переупаковывает поток из go2rtc в HLS без перекодирования (~3% одного ядра Pi 3). Сегменты пишутся в `/dev/shm`, чтобы не изнашивать SD-карту. Если плеер 30 сек не запрашивает поток, ffmpeg останавливается. Safari воспроизводит HLS сам. Остальные браузеры загружают [hls.js](https://github.com/video-dev/hls.js) с jsDelivr, поэтому им нужен доступ в интернет. Задержка HLS — несколько секунд. Поток 1080p в обоих режимах занимает около 3 Мбит/с.

Доступ к WebRTC из интернета: на роутере пробросьте порт 8555 (TCP и UDP) на Pi — больше ничего не нужно. Ответ go2rtc браузеру проходит через галерею, и она дописывает в него адрес, по которому открыто приложение (внешний IP или домен динамического DNS роутера, IP домена узнаётся через DNS), с портом 8555; смена IP у провайдера подхватывается сама. Дома, по локальному адресу, go2rtc сообщает локальные адреса Pi. go2rtc сообщает ещё и адрес, найденный через STUN; вручную задавать ничего не нужно. Через облако Zorcam проброс порта не нужен вовсе: видео ретранслирует TURN-сервер облака. go2rtc не собирает адреса через STUN для каждого зрителя (`ice_servers: []`): он отвечал только после этого сбора, и STUN-сервер, который не отвечает (например, попавший на роутере в маршруты через VPN), задерживал каждое открытие Live на 5 с. Если внешний порт на роутере отличается от 8555, поменяйте его в `candidates` в `app/go2rtc/go2rtc.yaml` и `WEBRTC_PORT` в `app/gallery/app.py`.

## Приложение на iPhone и вход

Галерею можно поставить на экран «Домой» как отдельное приложение. В Safari откройте галерею, нажмите «Поделиться», затем «На экран Домой». Пока галерея открыта в Safari на iPhone или iPad, в шапке видно яблоко Apple: по нажатию появляются эти шаги. Приложение открывается сразу во вкладке Live, без адресной строки и панелей Safari, со своей иконкой. В Android и в обычном браузере галерея работает как раньше; Chrome на Android тоже может предложить её установить.

Вход запоминается на год. Срок продлевается при каждом заходе, так что пока приложением пользуются, вход не истекает. Сессии хранятся в `/var/lib/zorcam-nvr/config/sessions.json` (права 600, только хэши токенов), поэтому переживают перезапуск галереи и Pi. Если сессия уже есть, страница входа сразу переводит в Live. Кнопка «Выйти» — на странице «Настройки» (вкладка «Настройки» в нижней панели); она удаляет сессию.

У приложения на экране «Домой» свои cookie, отдельные от Safari, поэтому в нём нужно войти один раз отдельно.

**Широкий экран.** На экране шириной от 1024 px (ноутбук) галерея — веб-приложение с боковой панелью слева (Live, Записи, Настройки, а внизу — кто вошёл) вместо нижней панели; содержимое — колонка по центру. Live показывает по 2, 3 или 4 камеры в ряд, «Видео» — сетка из 3–5 колонок с заголовками дней, которые при прокрутке остаются сверху, Timelapse — плеер, «Настройки» — список вкладок слева и выбранная вкладка справа, вход и мастер настройки — узкая колонка по центру. Меньше 1024 px (телефоны, планшеты вертикально) ничего не меняется. До всего можно добраться с клавиатуры (фокус обведён рамкой).

## Настройки

Вкладка «Настройки» в нижней панели открывает страницу «Настройки» для любой роли. Она разделена на вкладки: «Общие» — язык (см. «Язык»), у `admin` ещё «Общие настройки» (внешний IP-адрес для WebRTC); «Камеры» — камеры («Добавить камеру», «Изменить») и записи каждой камеры с кнопками удаления (см. «Хранение»); «Статус» — версия, состояние Zorcam и камер; «Польз.» — кто вошёл и «Выйти», у `admin` ещё все пользователи. На «Камерах» и «Статусе» в приложении на экране «Домой» страницу обновляет жест «потянуть вниз». «Камеры» и «Статус» видны только `admin`. На iPhone и на компьютере страница одинаковая.

**Разрешение камеры** — не больше 1080p, и настраивается оно в самой камере, а не в Zorcam (см. «Настройка камеры»).

**Камеры** хранятся в `/var/lib/zorcam-nvr/config/cameras.json`: для каждой — ID, название, RTSP-адрес без логина и пароля, логин, необязательный второй поток для детектора (см. «Настройка камеры»), уведомления о движении и настройки записи (см. «Хранение»). Пароли — в `/var/lib/zorcam-nvr/config/secrets.env` (права 600), строка на камеру: `ZORCAM_CAMERA_PASSWORD_<ID>` (ID заглавными, `-` становится `_`). Камеры добавляются в мастере настройки и в «Настройки» → «Добавить камеру»; «Настройки» → «Изменить» меняет камеру или удаляет её (с записями или без). Перед сохранением галерея спрашивает саму камеру (RTSP DESCRIBE); если та отвечает, например, `401 Unauthorized`, камера не сохраняется, пока не исправлен логин или не отмечено «Сохранить без проверки камеры». ID камеры — имя папок её записей и потока go2rtc, поэтому потом не меняется. Полную ссылку с паролем go2rtc собирает только при подключении (через `echo:python3 zorcam_config.py --rtsp-source <id>`), детектор и HLS берут поток у go2rtc. Новая или изменённая камера сразу появляется в Live, детектор и go2rtc перезапускаются сами.

**Недавний кадр.** У `admin` вверху формы камеры («Настройки» → «Изменить») виден самый новый сохранённый кадр камеры, а в «Настройки» → «Камеры» рядом с каждой камерой — маленькая миниатюра: сразу понятно, какая камера что снимает. Кадр берётся из тех, что устройство и так хранит (у камеры ничего дополнительно не запрашивается). Если кадров ещё нет (новая или выключенная камера), показывается плашка «Нет кадра».

**Зоны движения.** У `admin` в форме камеры («Настройки» → «Изменить») есть строка «Зоны движения». Она открывает кадр камеры с сеткой 16×9: клетки закрашиваются пальцем (касание или протяжка переключает их, страница при рисовании не прокручивается), затем выбирается «Исключить закрашенное» (закрашенные клетки не считаются) или «Только закрашенное» (считаются только они). Нет закрашенных клеток — зон нет. Детектор считает изменение только по учитываемым клеткам, от их площади, но не меньше 5% кадра, и рамка движения на постере не выходит за них; `motion_threshold` один на все камеры. Если исключено всё, экран предупреждает, что движение не будет обнаруживаться. Зоны лежат в `/var/lib/zorcam-nvr/config/motion_zones.json` (права 600; для каждого ID камеры — режим и 144 клетки `0`/`1` по строкам), а не в `cameras.json`: камера при сохранении не перезапускается, детектор замечает файл в течение нескольких секунд. При удалении камеры её зоны удаляются.

**Выключить камеру**, не удаляя её: тумблер рядом с ней в «Настройки» → «Камеры» (или «Изменить» → «Камера включена»). Выключенная камера не подключается, детектор и go2rtc её не трогают, в Live и облаке её нет, проверка «нет кадров» её не касается; её записи, настройки и пароль остаются, включается тем же тумблером (тогда камера проверяется, как при добавлении).

**Звук в Live и роликах**: «Изменить» → «Звук в Live и роликах» (по умолчанию выключен). Звук идёт так, как его отдаёт камера, без перекодирования на Pi (и в облаке): WebRTC играет G.711 (PCMA, PCMU) и Opus, HLS — AAC; с другим кодеком Live остаётся без звука. Видео запускается без звука (iPhone сам запускает только такое): кнопка с динамиком на плеере включает звук. Сохранённые ролики тоже получают звук, тоже без перекодирования, но только если камера отдаёт AAC (включается в самой камере): G.711 не помещается в куски MPEG-TS, из которых режутся ролики, и iPhone не играет его в mp4, поэтому ролики такой камеры остаются без звука. Детектор движения берёт только видео.

**Остальные параметры** — в `/var/lib/zorcam-nvr/config/zorcam.conf` (формат INI). `install.sh` создаёт его из `config/zorcam.conf.example`, где каждый параметр описан и закомментирован со значением по умолчанию.

| Раздел | Что задаёт |
|---|---|
| `[language]` | язык по умолчанию на устройствах, где язык не выбран: auto (язык устройства), en, ru |
| `[capture]` | порог движения, таймауты переподключения к камере |
| `[live]` | когда переключаться на HLS, когда останавливать HLS, внешний IP Pi для WebRTC (необязательно, см. «Live-трансляция») |
| `[notifications]` | как часто приходят уведомления о движении; уведомления о неисправностях: вкл/выкл, напоминания |
| `[health]` | как часто проверять систему и пороги: нет кадров, место на диске, температура |
| `[gallery]` | роликов на странице (10, 30 или 60), срок входа, стенд (`environment`: prod, stage или test) |

Как менять:
- **В приложении**, под ролью `admin`: в мастере настройки; внешний IP — «Настройки» → «Общие настройки»; остальные — на странице `/config` (ссылки на неё нет, адрес вводится вручную: `http://IP-адрес-Pi/config`). Каждое значение проверяется.
- **На Pi**: `sudo nano /var/lib/zorcam-nvr/config/zorcam.conf`.

В обоих случаях детектор и галерея сами замечают изменение `zorcam.conf` и перезапускаются (детектор — в течение 10 с). Проверить файлы: `sudo -u zorcam-nvr python3 /opt/zorcam-nvr/gallery/zorcam_config.py` покажет итоговые значения, камеры (без паролей) и ошибки. Параметр с ошибкой получает значение по умолчанию.

**Стенды (prod, stage, test).** Одна и та же сборка работает и на тестовых стендах. `environment` в `[gallery]` (по умолчанию `prod`, либо `stage`, либо `test`) говорит, какой это стенд. Для `prod` ничего не меняется. На `test` и `stage` в приложении виден значок TEST или STAGE рядом с названием Zorcam (в шапке на телефоне, в боковой панели на ноутбуке), заголовок страницы и имя под значком на экране «Домой» становятся `Zorcam test` или `Zorcam stage`, в «Настройки» → «Статус» появляется строка «Стенд», а адрес облака по умолчанию в «Настройки» → «Общие» → «Облако Zorcam» — облако этого стенда, `https://cloud.test.zorcam.ru` или `https://cloud.stage.zorcam.ru` (у `prod` — `https://cloud.zorcam.ru`). Уже сохранённый или привязанный адрес остаётся как есть. Чтобы задать стенд, добавьте строки в файл и перезапустите галерею (сама она замечает изменение в течение минуты):

```
sudo -u zorcam-nvr nano /var/lib/zorcam-nvr/config/zorcam.conf
sudo systemctl restart zorcam-nvr-gallery
```

```ini
[gallery]
environment = test
```

То же можно сделать на странице `/config`.

## Язык

Интерфейс, страницы «Настройки» и `/config`, сообщения мониторинга и push-уведомления есть на английском и русском.

**Язык выбирается на каждом устройстве** на странице «Настройки» (вкладка «Настройки» в нижней панели, любая роль): «Авто», English или «Русский». Выбор хранится на самом устройстве — в приложении на экране «Домой» или в браузере (cookie `zorcam_lang`), а не на Pi: он действует на все страницы этого устройства, в том числе на вход, и на push-уведомления, которые приходят на это устройство; на других устройствах того же пользователя язык свой. «Авто» — язык устройства (заголовок `Accept-Language`); если он не русский и не английский — английский.

Устройства, на которых язык не выбран, получают язык по умолчанию `[language] language` — первая настройка мастера и `/config`: `auto` (язык устройства), `en` или `ru`. Устройства, подписанные на push до появления переводов, получают уведомления на русском, пока в них снова не откроют приложение.

Все тексты интерфейса — в `app/common/zorcam_i18n.py`. Файлы настроек (`zorcam.conf`, `secrets.env.example`, `go2rtc.yaml`), скрипты установки и тесты — всегда на английском.

## Пользователи и роли

| Роль | Доступ |
|---|---|
| `liveviewer` | только Live: без записей и push; «Настройки» — язык и выход |
| `viewer` | Live, видео, кадры, push о движении; «Настройки» — язык и выход |
| `admin` | всё: то же + «Общие настройки», камеры, статус и пользователи в «Настройках», `/config`, удаление записей, push о неисправностях; администратор один, его имя — `admin` |

Мастер настройки создаёт только `admin`. Остальных пользователей `admin` добавляет в «Настройки» → «Польз.» → «Новый пользователь»: имя (без пробелов, до 32 символов; `admin` занято; регистр при входе неважен, поэтому `Slava` и `slava` — одно имя), роль — Viewer (`viewer`: Live, «Видео», Timelapse, уведомления о движении) или Live (`liveviewer`: только Live), пароль и доступные камеры (по умолчанию все). У каждого пользователя там же меняются роль, пароль (пусто — не менять; новый пароль завершает сессии этого пользователя на других устройствах) и доступ к каждой камере, и есть «Удалить пользователя»; у `admin` — только пароль. Имена в интерфейсе не меняются. Выключенная камера пропадает у пользователя из Live, «Видео» и Timelapse, её поток и файлы ему недоступны, push о движении на ней ему не приходят. Новая камера закрыта всем пользователям, кроме `admin`, пока он не включит её им в «Польз.»; после добавления камеры «Настройки» об этом напоминают. Все пользователи хранятся в `/var/lib/zorcam-nvr/config/users.json` (права 600, PBKDF2-хэши паролей, `cameras` — доступные пользователю камеры); их можно менять и на Pi (созданный командой пользователь камер не видит, пока их не включат в «Польз.»):
```bash
sudo -u zorcam-nvr python3 /opt/zorcam-nvr/gallery/zorcam_users.py set ИМЯ РОЛЬ   # создать или сменить пароль и роль (admin — только у admin); пароль спросит дважды
sudo -u zorcam-nvr python3 /opt/zorcam-nvr/gallery/zorcam_users.py del ИМЯ
sudo -u zorcam-nvr python3 /opt/zorcam-nvr/gallery/zorcam_users.py list
```
Удалённый пользователь сразу теряет доступ. Роль, изменённая командой, действует со следующего запроса.

## Мониторинг и самовосстановление

- **Детектор (`zorcam-nvr-capture`).** Если от камеры нет кадров дольше `stall_timeout` (15 с), ffmpeg перезапускается и детектор переподключается. Ждёт он не меньше трёх интервалов между ключевыми кадрами камеры (но не больше 60 с), поэтому камера с ключевым кадром раз в 10 с не считается пропавшей; первого кадра после подключения он ждёт до 60 с — на нагруженной Pi ffmpeg запускается и подключается десятки секунд. Пока камера не отвечает, пауза перед следующей попыткой удваивается — 3, 6, 12 … до 60 с — и возвращается к 3 с после минуты с кадрами: недоступная камера не запускает новый ffmpeg каждые несколько секунд. Если Pi не успевает кодировать (у кодировщика больше 3 роликов камеры), новый ролик из ключевых кадров не сохраняется (в журнале `encode queue full`, в «Настройки» → «Статус» — сколько за сутки), а не ждёт часами с кадрами в памяти. «Статус» ещё и следит за памятью детектора: если ядро постоянно притормаживает детекторы у `MemoryHigh` сервиса (`high` в `memory.events`), это проблема с push для admin — камер больше, чем тянет эта Pi. У RTSP в ffmpeg задан сетевой таймаут `rtsp_timeout`. Ошибки ffmpeg пишутся в журнал (`journalctl -u zorcam-nvr-capture`) без пароля камеры. При переподключении детектор ещё и спрашивает саму камеру (RTSP DESCRIBE) и добавляет её ответ, например `camera: 401 Unauthorized` или `camera: timed out`. Детектор анализирует в памяти каждый ключевой кадр и собирает из них ролики, но на SD-карту сохраняет кадр для Timelapse не чаще, чем задано в «Периодичности снимков» камеры (по умолчанию раз в 5 с), чтобы не изнашивать карту. Снимок, сохранённый после того, как детектор видел движение с прошлого снимка (или пока идёт пауза после срабатывания), называется `<дата>_<время>_<мс>_m.jpg` вместо `<дата>_<время>_<мс>.jpg`: метка `_m` ничего не стоит (кадры заново не разбираются), работает и при выключенном «Сохранять видео движения», а всё, что перечисляет, показывает, считает и удаляет снимки, обращается с обоими именами одинаково; таймлапс показывает метку. Пишет его отдельный поток: медленная карта не задерживает обнаружение движения и уведомления (пока она занята, снимки пропускаются), а ошибка записи, например когда нет места, не обрывает подключение к камере. Для анализа JPEG сразу декодируется в 1/8 размера в оттенках серого и сравнивается в 160×90, поэтому разрешение камеры на скорость реакции почти не влияет. ffmpeg детектора подключается без анализа потока (`-probesize 32 -analyzeduration 0`) и без многопоточного декодера (`-flags low_delay`): иначе он всё время отстаёт от камеры примерно на 1,4 с. JPEG он кодирует в один поток (`-threads 1`): так ffmpeg каждой камеры занимает примерно на 40 МБ меньше. Задержка реакции — в основном интервал между ключевыми кадрами (0,4 с при 2,5 кадра/с). Для каждой камеры детектор запускает отдельный процесс (`daemon.py --camera <id>`, строки в журнале начинаются с `[<id>]`), поэтому зависшая камера не останавливает остальные; завершившийся или не отвечающий 60 с процесс перезапускается. Постер ролика — кадр, на котором сработал детектор (второй из двух сравниваемых кадров); он записывается сразу: пока ролик пишется и склеивается, «Видео» показывает его с надписью «Видео готовится…», а когда файл готов, страница за несколько секунд превращает карточку в ролик. По тем же малым кадрам 160×90 детектор находит область, где изменилась картинка (пиксели, отличающиеся на 28 и больше из 255, одиночные точки отброшены; если изменился весь кадр — области нет), и записывает её вместе с моментом движения в ролике (первый из двух сравниваемых ключевых кадров, последний без движения: рамка — разница между ними; секунды от начала, до 0,1 с; точность около секунды-двух: куски названы целыми секундами) в `<ролик>.json` в несколько десятков байт рядом с постером; в сам файл постера ничего не рисуется. «Видео» и страница ролика кладут по нему красную рамку поверх постера; страница ролика, когда воспроизведение доходит до этого момента, зажигает значок «Движение» и рамку, а засечка на шкале под видео (нажатие переводит к ней) показывает, где он. У роликов без `.json` (записанных раньше) этого нет. `.json` удаляется вместе с роликом. Если связь с камерой оборвалась посреди ролика, записанное всё равно сохраняется. Ролик, который остановленный процесс не дописал, помечается несохранённым: на его постере — надпись «Could not save the video» (новый процесс делает это в фоне, уже следя за движением). Каждый пишет своё состояние (последний кадр, переподключения за сутки, последняя ошибка) в `/dev/shm/zorcam_capture_<id>.json`.
- **Watchdog systemd.** Детектор и галерея регулярно сообщают systemd, что живы (`WatchdogSec`). Галерея делает это, только пока отвечает на `/healthz`. Зависший процесс systemd перезапустит сам.
- **Ограничения памяти и процессора.** У каждого сервиса в юните systemd есть предел (`MemoryMax`: детектор — 61% памяти, go2rtc — 22%, галерея — 250 МБ; на Pi 3 это прежние 560 МБ и 200 МБ, на Pi 4/5 пределы растут вместе с памятью; без подкачки; `CPUQuota`, низкий `CPUWeight`). Сервис, вышедший за предел, systemd завершает и перезапускает, а остальная Pi и SSH остаются доступны. Текущий расход памяти показывает `systemctl status zorcam-nvr-gallery`. На Raspberry Pi ядро по умолчанию загружается с `cgroup_disable=memory`, и пределы памяти не действуют: `install.sh` добавляет `cgroup_enable=memory` в `/boot/firmware/cmdline.txt` (старый файл — `cmdline.txt.bak`), пределы начинают работать после перезагрузки (`sudo reboot`). Ролики кодируются по одному на все камеры, не больше чем в 2 потока и без предпросмотра кадров (`-tune zerolatency`, около 120 МБ на 1080p) и с низшим приоритетом (`nice 19`), чтобы детекторы не теряли кадры: несколько кодирований сразу съедали память Pi 3. Выше `MemoryHigh` (у детектора — 52% памяти, на Pi 3 — 480 МБ) ядро притормаживает все процессы сервиса, и детекторы теряют кадры: в `memory.events` в `/sys/fs/cgroup/system.slice/zorcam-nvr-capture.service/` это счётчик `high`. Кэш страниц записанных сервисом файлов тоже входит в его память, поэтому детектор сбрасывает каждый снимок и ролик на карту и убирает его из кэша: галерея прочитает его с карты, когда его откроют. Временные файлы в `/dev/shm` принадлежат системному пользователю `zorcam-nvr`, а их systemd-logind не трогает (файлы обычных пользователей он удаляет, когда закрывается их последний сеанс, `RemoveIPC`), поэтому выход из SSH не стирает буферы «Всего потока», HLS и превью. Если буфер «Всего потока» всё же пропал, детектор создаёт его заново.
- **Проверка раз в минуту (галерея).** Проверяются: есть ли свежие кадры с каждой камеры, работают ли `zorcam-nvr-capture` и `zorcam-nvr-go2rtc`, свободное место, температура CPU. При проблеме на устройства, подписанные пользователями `admin`, приходит push «⚠ Zorcam: …» с причиной (например, `401 Unauthorized` от камеры). Если проблема не устранена, напоминание приходит раз в час. После восстановления приходит «✓ Zorcam: … снова в норме». Нажатие открывает страницу «Настройки».
- **HTTP-соединения.** Галерея говорит по HTTP/1.1 и держит соединения открытыми (60 с простоя), поэтому страница с десятками превью или таймлапс не открывает соединение на каждый файл; через облако каждое новое соединение — новый канал туннеля. Ответ без длины тела (ошибка, перенаправление) и любой ответ на POST закрывают соединение, чтобы непрочитанное тело запроса не приняли за следующий запрос. `/healthz` и watchdog systemd не изменились; у каждого соединения свой поток.
- **Очистка.** Раз в 10 минут галерея удаляет кадры и ролики старше сроков каждой камеры («Хранить видео, дней» и «Хранить снимки, дней» в настройках камеры); папки удалённых камер — по срокам по умолчанию. Если свободного места всё равно меньше `[health] min_free_disk_mb` (по умолчанию 1024 МБ), галерея сразу удаляет самые старые снимки и ролики всех камер (ролик — вместе с постером), пока свободно не станет на 512 МБ больше, и присылает администраторам push (не чаще раза в сутки); каждая такая очистка видна в «Настройки» → «Статус».

## Push-уведомления о движении

Когда детектор замечает движение, галерея присылает на подписанные устройства пользователей `viewer` и `admin` уведомление «Движение — <название камеры>, ЧЧ:ММ:СС» (на языке пользователя, см. «Язык»). Нажатие на уведомление открывает Live. Уведомления приходят не чаще раза в минуту для каждой камеры. У каждой камеры свой тумблер «Уведомления о движении» («Настройки» → «Изменить»): если он выключен, движение на этой камере push не присылает.

Включаются кнопкой с колокольчиком в шапке, отдельно на каждом устройстве. Сразу после включения приходит проверочное уведомление. Повторное нажатие выключает уведомления на этом устройстве.

Каждый пользователь (`viewer` и `admin`) сам выбирает, о чём получать уведомления, в «Настройки» → «Уведомления»: общий переключатель «Все камеры» и переключатель каждой доступной ему камеры. Переключатели работают сразу, кнопки «Сохранить» нет, выбор действует для учётной записи на всех устройствах. Включение камеры там включает и её тумблер «Уведомления о движении» в настройках камеры (для всех пользователей, если он был выключен); выключение касается только самого пользователя.

- **iPhone.** Нужна iOS 16.4+, а уведомления работают только в приложении с экрана «Домой».
- **HTTPS.** Галерея должна быть открыта по HTTPS (например, через домен динамического DNS роутера с сертификатом). По `http://` браузер не разрешит подписку. Приложение на экране «Домой» нужно добавлять уже с HTTPS-адреса.
- **Как устроено.** `zorcam-nvr-capture` сообщает о движении галерее через `POST http://127.0.0.1/internal/motion`, запросы не с localhost отклоняются. Галерея шифрует уведомление и отправляет его в push-сервис браузера (Apple, Google, Mozilla) по стандарту Web Push с VAPID. Код в `app/gallery/push.py`, из зависимостей только `python3-cryptography`.
- **Файлы.** Ключ VAPID и подписки хранятся в `/var/lib/zorcam-nvr/config/vapid_private.pem` и `push_subscriptions.json` (права 600). Если удалить ключ, все устройства нужно будет подписать заново.

## Облако Zorcam

По желанию владельца: открывать Pi откуда угодно без проброса портов и белого IP, все свои Pi в одном приложении, вход через Яндекс ID, доступ для семьи. Без облака Zorcam работает как прежде, облако не нужно для записи, галереи и push. Записи и снимки остаются на Pi: облако их не хранит и паролей камер и галереи не получает. Live через облако идёт по WebRTC и без проброса порта 8555: видео ретранслирует TURN-сервер облака (шифрование от Pi до телефона, DTLS-SRTP), временные логины облако передаёт галерее. Облако работает в России, сначала бесплатно.

1. **Подключить.** «Настройки» → «Общие» → «Облако Zorcam» → адрес облака → «Подключить». Галерея покажет код на 10 минут.
2. **Ввести код.** В облачном приложении (`https://cloud.<домен облака>`, войти через Яндекс ID) → «Подключить Pi» → код. Через несколько секунд Pi на связи: галерея открывается по адресу `https://<id>.<домен облака>` под тем же пользователем галереи, без её пароля (владелец входит как `admin`).
3. **Пригласить.** В приложении: «Устройства» → Pi → «Пригласить» → имя пользователя галереи (роль и камеры задаются как обычно, «Настройки» → «Польз.»). Ссылка на 7 дней, на один вход через Яндекс ID.

Как устроено: сервис `zorcam-nvr-cloud` (от пользователя `zorcam-nvr`) после привязки держит туннель frpc к облаку по `wss` через порт 443 (Pi подключается сама, порты на роутере не нужны) и раз в минуту сообщает, что на связи. Облако подтверждает каждый запрос подписанным токеном на 60 с (`X-Zorcam-Identity`, ключ облака получен при привязке); галерея принимает его только от туннеля (127.0.0.1) и дальше применяет роль и камеры этого пользователя из `users.json`. О движении облако узнаёт только камеру и время, без снимка. Состояние — `/var/lib/zorcam-nvr/config/cloud.json` (права 600). Отвязать — «Отвязать от облака» в галерее или в приложении. Журнал — `journalctl -u zorcam-nvr-cloud`.

**Таймлапс.** Вкладка Timelapse (раньше «Снимки») — таймлапс снимков (и дома, и через облако; сетки снимков больше нет, а старые ссылки на неё, с `mode=`, `horizon=` или `fpage=`, открывают ту же вкладку). Он показывает снимки за «Сегодня» (с полуночи; любой другой день — в календаре под плеером) как видео, 15 кадров в секунду, с паузой, ползунком положения и временем кадра по часовому поясу Pi (например, `10:53:28 11.10.2026 MSK`; пояс без буквенного обозначения показывается как `UTC+03:00`) — над кадром слева внизу. Кнопки скорости — множители реального времени: по умолчанию (средняя) играются все снимки подряд, то есть быстрее жизни в «интервал снимков × 15 кадров в секунду» раз (при интервале 5 с — ×75: 75 секунд жизни за секунду), остальные четыре — в четверть, половину, вдвое и вчетверо от этого (×19, ×38, ×75, ×150, ×300; от 1000 число пишется как `1.5k`; подсказка кнопки — `75× реального времени`). Интервал берётся из загруженных кадров (медианный промежуток между соседними снимками), а скорость по умолчанию выбирается заново при каждой загрузке периода или дня. Медленные кнопки показывают каждый кадр с меньшей частотой (четверть и половина от 15 в секунду), быстрые пропускают каждый второй или четвёртый кадр; если снимков меньше двух, интервал неизвестен, и кнопки показывают просто ×0.25 … ×4. Под ползунком полоска отмечает красным кадры, сохранённые после движения (снимки `_m`); нажатие на полоску переходит к этому месту, а если у движения есть сохранённый ролик, над меткой появляется ссылка «Видео чч:мм:сс» на него (`/timelapse` отдаёт ещё `videos` — сохранённые ролики периода — и `clip` — длину ролика). Ниже красных отметок на полоске — отметки суток (линия подлиннее и дата `дд.мм`) и часов (короткая линия и номер часа там, где он помещается; шаг 1, 2, 3, 6 или 12 часов подбирается по ширине экрана). Пауза в записи дольше трёх интервалов снимков и минуты (камеру выключали или она не отвечала) занимает на полоске и ползунке своё настоящее время и видна разрывом: полоска в этом месте пустая, по краям — риски, часы внутри разрыва стоят на своих местах; нажатие или ползунок внутри разрыва переходят к ближнему его краю. Кадры не прореживаются: плеер получает все снимки периода, поэтому сутки при коротком интервале снимков — длинное видео (сутки при 5 с по умолчанию — около 17 000 кадров, 19 мин при ×1) и список в несколько сотен КБ. Pi отдаёт только список имён файлов, компактно (время и отметку движения плеер берёт из самих имён), с gzip-сжатием, если браузер его просит (примерно в 10 раз меньше), и держит не больше 6 готовых ответов по 20 с; На компьютере, пока таймлапс на экране, работает клавиатура: пробел — пуск и пауза, стрелки влево и вправо — кадр назад и вперёд (с Shift — на 10 кадров), Home и End — к первому и последнему кадру. Под плеером — календарь: ряд дней, самый ранний слева, сегодня справа, над первым днём месяца — его название. Нажмите день — загрузятся и начнут играть его снимки (выбор запоминается на устройстве). Под числом у каждого дня два значка на постоянных местах: слева стопка кадров с треугольником «пуск» поверх (цвета текста) — у дня есть таймлапс, то есть снимки, справа камера (цвета текста) — есть ролики движения. Чего у дня нет, того значок бледный, поэтому ячейки выровнены; день без снимков затемнён и не нажимается, день только с роликами — тоже. Ролики, которые не сохранились, не считаются. Клавиши `[` и `]` — к предыдущему и следующему дню со снимками. Телефон подгружает кадры с опережением по несколько штук в виде превью 320×180 и выгружает уже показанные, так что его память почти не нагружается. Список отдаёт `/timelapse/<ID камеры>?period=hour|today` (или `?day=ГГГГ-ММ-ДД` — один календарный день по времени Pi, с 00:00:00 до 23:59:59; календарь берётся из `?days=1`: каждый день от самого раннего со снимками или роликами до сегодня, не больше 400, с числом снимков и роликов за день — по именам файлов, с кэшем на 20 с, как списки кадров) (viewer и admin, только камеры, которые видит пользователь); папка читается по именам файлов, ни один файл не открывается (сутки при коротком интервале снимков — тысячи имён, поэтому «Хранить снимки, дней» ставьте столько, на сколько хотите смотреть назад).

Раз в час подключённая Pi ещё отправляет в облако отчёт о самочувствии для админки облака: версию, время работы, нагрузку, свободную память и диск, температуру процессора, состояние и счётчики памяти сервисов Zorcam, по каждой камере — её ID, возраст последнего кадра и число переподключений за 24 ч, и итоги «Настройки» → «Состояние» (тексты — только у проблем). Названий камер, адресов, паролей, записей и снимков в нём нет. Тот же отчёт администратор облака может запросить сразу («Запросить состояние» в админке): облако спрашивает галерею через туннель от имени владельца. Облако хранит отчёты 7 дней.

## Умный дом Яндекса

Каждая камера может стать датчиком движения в «Доме с Алисой», и на него вешаются сценарии: колонка говорит «кто-то у двери», включается свет. Видео в Яндекс не передаётся, только название камеры и «движение» / «нет движения». Zorcam работает как приватный навык умного дома, к которому Яндекс обращается через [облако Zorcam](#облако-zorcam): навыку нужен Pi, подключённый к облаку («Настройки» → «Общие» → «Облако Zorcam»), по его адресу `https://<id>.<домен облака>`. Без облака раздел в настройках только объясняет это, а адреса навыка на Pi не отвечают. Если позже отключить облако, ключи навыка и связка сохраняются и снова работают после подключения; уведомления в это время не отправляются.

1. **Навык.** На [dialogs.yandex.ru/developer/smart-home](https://dialogs.yandex.ru/developer/smart-home) создайте навык умного дома, тип доступа — приватный. Значения для Backend и «Связки аккаунтов» показывает страница «Настройки» → «Общие» → «Умный дом Яндекса» (страница показывает адреса готовыми, по адресу вашего Pi в облаке): Endpoint URL `https://<id>.<домен облака>/yandex`, идентификатор приложения `zorcam`, URL авторизации `https://<id>.<домен облака>/yandex/auth`, URL получения и обновления токена `https://<id>.<домен облака>/yandex/token`. Секрет приложения придумайте сами. Сохраните и нажмите «Опубликовать»: уведомления работают только у опубликованного навыка, черновик не подойдёт.
2. **Ключи.** На той же странице Zorcam введите секрет приложения, ID навыка («Общие сведения» навыка) и OAuth-токен для уведомлений: войдите аккаунтом владельца навыка и откройте ссылку со страницы — Яндекс покажет токен.
3. **Связка.** В «Доме с Алисой»: + → «Устройство умного дома» → ваш навык → «Привязать к Яндексу», войдите как `admin`. Камеры появятся как датчики движения.
4. **Сценарий.** «Сценарии» → + → «Если»: устройство → камера → «Движение»; «То»: колонка → произнести фразу.

Датчик сообщает «движение» один раз на эпизод и «нет движения» через минуту тишины детектора, не зависит от тумблера push у камеры. Отвязать можно в «Доме с Алисой» или кнопкой на странице Zorcam (страница открывается дома и через облако, под admin). Неверные пароли и секреты на адресах навыка считаются и блокируются по адресу клиента, который облако передаёт Pi. Выданные Яндексу токены хранятся хешами в `/var/lib/zorcam-nvr/config/yandex.json` (права 600) вместе с секретом и токеном навыка. Код в `app/gallery/yandex.py`; что отправлено и что ответил Яндекс — `journalctl -u zorcam-nvr-gallery | grep yandex`.

## Оборудование

Zorcam работает на Raspberry Pi 3 с одной камерой, но Pi чаще всего зависает из-за блока питания или SD-карты, а не из-за программы. Что использовать:

| Компонент | Рекомендация | Почему |
|---|---|---|
| Raspberry Pi | Pi 4 (2 ГБ и больше) или Pi 5; минимум — Pi 3 Model B/B+ (1 ГБ) | Pi 3 справляется с одной камерой 1080p, у Pi 4/5 есть запас памяти и процессора, USB 3 и более быстрый слот SD-карты. Меньше 1 ГБ (Pi Zero 2 W, 512 МБ) не поддерживается: не больше 1-2 камер, `install.sh` предупреждает. Пределы памяти детектора и go2rtc заданы процентами от памяти |
| Система | Debian 13 (Raspberry Pi OS Lite, 64 бит), без рабочего стола | рабочий стол занимает память, нужную сервисам |
| Блок питания | официальный блок Raspberry Pi: 5,1 В 2,5 А micro-USB для Pi 3, 5,1 В 3 А USB-C для Pi 4, 5,1 В 5 А (27 Вт) USB-C для Pi 5 | с зарядкой от телефона или длинным тонким кабелем напряжение проседает под нагрузкой: процессор замедляется, SD-карта перестаёт отвечать, и зависает вся Pi, включая SSH |
| SD-карта | High Endurance на 32–64 ГБ, A1/A2, U3/V30 (например, SanDisk High/Max Endurance, Samsung PRO Endurance) | детектор круглосуточно пишет кадры и ролики, обычные карты изнашиваются и начинают зависать. На Pi 4/5 (и Pi 3B+) ещё лучше загрузка с USB SSD |
| Охлаждение | радиаторы, корпус с вентиляцией, не на солнце | выше 80 °C процессор замедляется (троттлинг) |
| Сеть | Ethernet для Pi и камеры | поток ~3 Мбит/с идёт постоянно, Wi-Fi 2,4 ГГц у Pi 3 медленнее и менее стабилен |
| ИБП (по желанию) | UPS HAT или небольшой ИБП для Pi и камеры | отключение питания во время записи может повредить файловую систему на SD-карте |

Как проверить Pi после установки:

```bash
vcgencmd get_throttled   # 0x0 — с момента загрузки не было ни просадок напряжения, ни троттлинга
vcgencmd measure_temp    # в обычной работе ниже 70 °C
```

Любое значение, кроме `0x0`, значит, что блок питания или кабель слишком слабые (`0x50000` — напряжение проседало и процессор замедлялся). Как искать причину зависаний — в разделе «Отладка».

## Установка

Все команды выполняются на Pi под пользователем с правами `sudo`, например `admin`, в любой папке: пути в командах полные. Сами сервисы работают от отдельного системного пользователя `zorcam-nvr` (без пароля, входа и `sudo`): программа — в `/opt/zorcam-nvr` (только для чтения), настройки — в `/var/lib/zorcam-nvr/config` (читает только `zorcam-nvr`), записи — в `/var/lib/zorcam-nvr/recordings` (`install.sh` добавляет вашего пользователя в группу `zorcam-nvr`, чтобы их можно было читать). Нужны Raspberry Pi с Debian 13 (Raspberry Pi OS), права `sudo`, доступ в интернет и IP-камера, отдающая RTSP-поток в H.264.

### Шаг 1. Доступ к репозиторию

Репозиторий публичный: настраивать ничего не нужно, переходите к шагу 2.

### Шаг 2. Скачать программу

```bash
sudo apt update && sudo apt install -y git      # в Raspberry Pi OS Lite git нет
git clone https://github.com/davydovv-creator/zorcam-nvr-community.git ~/zorcam-nvr
```

### Шаг 3. Установка

```bash
~/zorcam-nvr/app/install.sh
```

Скрипт ставит пакеты (`ffmpeg`, `python3-pil`, `python3-cryptography`, `curl`) и go2rtc, создаёт системного пользователя `zorcam-nvr` и его папки в `/var/lib/zorcam-nvr`, раскладывает программу в `/opt/zorcam-nvr`, создаёт `/var/lib/zorcam-nvr/config/zorcam.conf` со значениями по умолчанию, устанавливает и запускает сервисы `zorcam-nvr-capture`, `zorcam-nvr-gallery` и `zorcam-nvr-go2rtc` и при включённом ufw открывает порт 8555. Ничего не спрашивает и заканчивается строкой «Done.» с адресом, который нужно открыть.

**Часовой пояс.** Записи и снимки называются по часам Pi в её часовом поясе, и галерея с таймлапсом показывают это время; пояс виден в «Настройки» → «Статус» (например, `Europe/Moscow (UTC+03:00)`). Свежая Raspberry Pi OS часто стоит в UTC. Поставить московское время:

```bash
sudo timedatectl set-timezone Europe/Moscow
sudo systemctl restart zorcam-nvr-capture zorcam-nvr-gallery
```

Перезапуск нужен: работающий сервис держит пояс, с которым запустился (до перезапуска «Статус» показывает новый пояс красным). Записи, сделанные до смены, сохраняют свои имена.

### Шаг 4. Настройка в браузере

В браузере в домашней сети откройте `http://<IP Pi>/` (IP показывает `hostname -I`). Пока нет пользователей, галерея открывает мастер настройки; он работает только из домашней сети, чтобы никто из интернета не занял его раньше вас.

1. **Общие настройки.** Язык. Остальные настройки — под «Другие настройки», значения по умолчанию подходят большинству. Для Live из интернета пробросьте на роутере порт 8555 (TCP и UDP) на Pi (см. «Live-трансляция»).
2. **Администратор.** Пароль `admin`. Остальных пользователей добавите потом в «Настройки» → «Польз.». После этого шага вы вошли как `admin`.
3. **Камеры.** «Готовы добавить камеру?» Да: ID камеры (латинские буквы, цифры, `-` и `_`: папки записей `/var/lib/zorcam-nvr/recordings/<id>` и `<id>_videos`), её название (над её плеером Live, на её вкладке и в уведомлениях), RTSP-адрес из настроек камеры без логина и пароля, логин (по умолчанию `admin`), пароль (пусто — камера без авторизации) и настройки записи. Форма показывает рекомендуемые настройки камеры (см. «Настройка камеры») и проверяет, что камера отвечает. Затем можно добавить ещё камеру или закончить. Камеры можно добавить и позже: «Настройки» → «Добавить камеру».

### Шаг 5. Открыть галерею

После мастера галерея открывается на Live: у каждой камеры должно быть LIVE (WebRTC); LIVE · HLS значит, что WebRTC не подключился. Повторный запуск `~/zorcam-nvr/app/install.sh` проверяет каждую камеру: «camera <id> connects, codec H.264» (или «codec H.265»: Live такой камеры показывает любой браузер на iPhone и iPad и Safari на Mac; если Chrome или Firefox на Android или компьютере не показывает картинку, переключите её на H.264, см. «Настройка камеры»).

Из интернета: для Live пробросьте на роутере порт 8555 (TCP и UDP) на Pi, а галерею откройте по HTTPS-адресу (например, через домен динамического DNS вашего роутера с сертификатом); push-уведомлениям нужен HTTPS. Сам порт 80 наружу не пробрасывайте: галерея отдаёт обычный HTTP, пароль и сессия пошли бы по интернету открытым текстом; проще всего безопасно открыть её извне — через облако Zorcam. На iPhone поставьте галерею на экран «Домой»: в Safari нажмите иконку приложения в шапке и выполните шаги (см. «Приложение на iPhone и вход»).

### Что делает install.sh

Каталоги репозитория раскладываются так:

| Репозиторий | На устройстве |
|---|---|
| `app/capture/` | `/opt/zorcam-nvr/capture/` |
| `app/gallery/` | `/opt/zorcam-nvr/gallery/` |
| `app/go2rtc/` | `/opt/zorcam-nvr/go2rtc/` |
| `app/common/*.py` | в оба каталога: `/opt/zorcam-nvr/capture/` и `/opt/zorcam-nvr/gallery/` |
| systemd-юниты (`zorcam-nvr-go2rtc-config.path` перезапускает go2rtc при изменении `zorcam.conf`, `cameras.json` или `secrets.env`) | `/etc/systemd/system/` |
| go2rtc | `/usr/local/bin/go2rtc` |

Zorcam с версии 0.1.5 ставится на чистую Pi. Установка под прежним именем zorcam (пользователь `zorcam`, `/opt/zorcam`, `/var/lib/zorcam`, сервисы `zorcam-*`) переименовывается один раз. Пользователь становится `zorcam-nvr`, настройки и записи переезжают в `/var/lib/zorcam-nvr`, старые сервисы и папка программы удаляются; записи, пользователи, подписки push и привязка к облаку сохраняются. Клон можно оставить на месте или перенести: `mv ~/zorcam ~/zorcam-nvr`. Повторный запуск скрипта безопасен: обновляется только изменившееся и перезапускаются только затронутые сервисы. Галерея слушает порт 80 через `AmbientCapabilities=CAP_NET_BIND_SERVICE`, работая от пользователя `zorcam-nvr` (`NoNewPrivileges`, `ProtectSystem=full`, `ProtectHome=yes`: он не может получить права, изменить систему или прочитать домашние папки). Очистку старых кадров и роликов делает сама галерея по срокам каждой камеры в `cameras.json`.

## Хранение

| Данные | Срок |
|---|---|
| Снимки | 10 дней (`frames_days` камеры) |
| Видео | 5 дней (`videos_days` камеры) |

У каждой камеры свои настройки («Настройки» → камера → «Изменить»): «Сохранять видео движения» (если выключено, движение всё равно определяется и приходят уведомления, но ролики не пишутся), «Длина видео, секунд» (от 2 до 120, по умолчанию 10), «Хранить видео, дней» (от 1 до 365), «Сохранять снимки» (если выключено, вкладка Timelapse камеры пуста), «Периодичность снимков, секунд» (от 1 до 3600, по умолчанию 5) и «Хранить снимки, дней» (от 1 до 365). Поля видео активны, только когда включено «Сохранять видео движения», поля снимков — только когда включено «Сохранять снимки»; значения неактивных полей сохраняются. Снимок раз в 5 секунд — примерно 1–2 ГБ в день на камеру.

Ролики движения на Pi не перекодируются. Отдельный ffmpeg всё время режет видео камеры от go2rtc на куски по 2 секунды без перекодирования, в оперативной памяти (`/dev/shm/zorcam_rec_<id>`, SD-карта не изнашивается); при движении куски от 3 с до него и до конца ролика склеиваются в `.mp4`, тоже без перекодирования. У ролика полная частота кадров и разрешение камеры, процессор почти не нужен, но файлы в разы больше (битрейт камеры: при 4 Мбит/с около 5 МБ за 10 с) — сократите «Хранить видео, дней» или уменьшите битрейт в камере. Куски в памяти (длина ролика плюс около 30 с, примерно 20 МБ при 4 Мбит/с) входят в предел памяти `zorcam-nvr-capture`. Лучше H.264: ролик и Live в H.265 показывают iPhone, iPad и Safari на Mac, но не каждый браузер на Android и компьютере. Если кусков нет (камера или go2rtc в тот момент были недоступны), ролик не сохраняется: в «Видео» остаётся только его постер с надписью «Could not save the video» (на Pi ничего не кодируется).

**Записи на USB-диске.** «Настройки» → «Общие» → «Диск для записей» (admin): подключённые к Pi USB-флешки и диски (никогда не SD-карта и не диск, с которого загружается Pi). «Отформатировать … и записывать на него» стирает диск и форматирует его (ext4); «Подключить … без форматирования» берёт диск, уже размеченный в ext4 (например, ранее работавший с Zorcam), как есть. Записи с SD-карты переносятся на диск, дальше снимки и ролики пишутся туда: SD-карта больше не изнашивается от них. Делает это сервис `zorcam-nvr-storage` (от root): при загрузке до детектора и раз в минуту. Если диск пропал (вынули, отказал), запись продолжается на SD-карту, в «Статусе» — проблема «Диск для записей» (push администратору); диск вернулся — он подключается снова, и записанное за это время переносится на него. «Отключить диск» прекращает запись на него (записанное остаётся), после этого его можно вынуть. Надёжнее всего USB-SSD; жёсткому диску 2,5″ нужно своё питание или хаб с питанием (USB-порты Pi 3 вместе дают около 1,2 А). Сроки хранения камеры можно увеличить: очистка по свободному месту смотрит на тот диск, где лежат записи.

Удалить записи вручную может пользователь с ролью `admin`, для каждой камеры отдельно: «Настройки» → «Камеры» → «Записи», под названием камеры. «Удалить» под Timelapse очищает Timelapse этой камеры, её ролики остаются; «Удалить» под «Видео» удаляет её ролики с движением; «Удалить все» под ними удаляет и то, и другое. Перед удалением приложение спрашивает подтверждение, после удаления просто снова показывает ту же вкладку «Настроек» (страницы с результатом нет; счётчики камеры обновляются).

## Настройка камеры

**Поиск камер (ONVIF).** В форме новой камеры кнопка «Найти камеры в сети (ONVIF)» отправляет в домашнюю сеть поиск ONVIF (WS-Discovery) и показывает ответившие камеры с адресом и моделью; уже добавленные помечены. Введите логин и пароль камеры и нажмите «Добавить»: Zorcam прочитает её видеопрофили и заполнит форму — RTSP-адрес с самой большой картинкой и «Дополнительный поток» для детектора — следующий за ним поток камеры меньшего разрешения (третий поток у многих камер слишком мелкий или в MJPEG). Проверьте поля и сохраните; пароль, введённый для ONVIF, сохранится для камеры и на странице не показывается. ONVIF в камере должен быть включён (у некоторых он выключен или нужен отдельный пользователь ONVIF, например «аккаунт камеры» у Tapo); запросы идут только на адреса домашней сети. Камеры в другой подсети за роутером (например, 192.168.2.x, когда Pi в 192.168.1.x) этот поиск не слышат: роутер его туда не пропускает. Укажите эту подсеть внизу страницы, в «Поиск» → «Другая подсеть» (например, `192.168.2.0`: без маски — вся 192.168.2.x; только домашние сети, до 254 адресов), и нажмите «Искать снова»: Pi спросит каждый её адрес напрямую; роутер должен пропускать UDP на порт 3702 между подсетями. Подсеть запоминается на устройстве (cookie), пустое поле — снова только сеть Pi. Камера не нашлась — введите её вручную.

В веб-интерфейсе или приложении камеры настройте поток, который использует Zorcam (его RTSP-адрес — в форме камеры); те же рекомендации показывает форма камеры в галерее:

| Параметр | Значение |
|---|---|
| Кодек | H.264 (H.265 — если смотрите на iPhone, iPad или в Safari на Mac) |
| Частота кадров | 25 fps |
| Интервал I-кадров (key-frame interval) | 10 кадров |
| Разрешение | не больше 1080p (1920×1080) |

**Разрешение камеры настоятельно рекомендуется задать не больше 1080p — и задавать его в самой камере, а не в Zorcam.** Zorcam берёт поток таким, каким его отдаёт камера: Live, детектор движения и ролики получают полное разрешение. Если у камеры основной поток больше 1080p, укажите в Zorcam RTSP-адрес второго потока (sub stream) с разрешением 1080p или ниже.

**Второй поток для детектора.** Большинство камер отдают ещё и второй, облегчённый поток (sub stream, например 640×360). Укажите его RTSP-адрес в форме камеры, поле «Дополнительный поток» (сразу под RTSP-адресом) (логин и пароль те же). Тогда детектор движения, снимки и постеры роликов работают по нему, а Live и ролики движения — по основному, в полном качестве. Ключевой кадр 640×360 декодируется в разы дешевле 1080p, поэтому Pi 3 тянет 4–5 камер вместо 2–3. Второй поток в камере настройте так: H.264, около 640×360, ключевой кадр раз в секунду. Если он 3 подключения подряд не даёт кадров, детектор на 30 минут переходит на основной поток и потом пробует снова; какой поток он смотрит, видно в «Настройки» → «Статус». go2rtc при этом держит два подключения к камере, по одному на поток; большинство камер это допускают. Обычные адреса (сверьте в камере):

| Камера | Основной поток | Второй поток |
|---|---|---|
| Hikvision | `rtsp://IP:554/Streaming/Channels/101` | `rtsp://IP:554/Streaming/Channels/102` |
| Dahua, Amcrest | `rtsp://IP:554/cam/realmonitor?channel=1&subtype=0` | `rtsp://IP:554/cam/realmonitor?channel=1&subtype=1` |
| TP-Link Tapo | `rtsp://IP:554/stream1` | `rtsp://IP:554/stream2` |
| Reolink | `rtsp://IP:554/h264Preview_01_main` | `rtsp://IP:554/h264Preview_01_sub` |
| Другие | `…/MAIN`, `…/main` | часто `…/SUB`, `…/sub`; оба показывает ONVIF Device Manager |

Почему именно так:
- **H.264.** Его по WebRTC показывают все браузеры; H.265 — любой браузер на iPhone и iPad и Safari на Mac. У Raspberry Pi 3 нет аппаратного декодера H.265, поэтому второй поток для детектора — точно H.264.
- **25 fps.** Live показывает все кадры, картинка остаётся плавной.
- **Не больше 1080p.** У Pi 3 — 1 ГБ памяти и нет аппаратного декодера: каждый ключевой кадр каждой камеры декодируется процессором, а кодирование ролика 1080p занимает около 120 МБ памяти. С потоком 2K или 4K детектор не успевает, ролики кодируются долго и упираются в предел памяти сервиса.
- **I-кадр каждые 10 кадров.** Детектор декодирует только ключевые кадры, поэтому получает 25 / 10 = 2.5 кадра в секунду: чем их больше, тем быстрее он замечает движение (Timelapse хранит из них один раз в «Периодичность снимков» камеры). Задавать это число в Zorcam не нужно: детектор сам меряет, сколько ключевых кадров приходит (видно в «Настройки» → «Статус»). При нескольких камерах держите частоту ключевых кадров не выше 5: Pi 3 декодирует каждый ключевой кадр каждой камеры.

## Отладка

Если Pi зависает или что-то не работает и причина неясна, включите расширенную отладку:

```bash
~/zorcam-nvr/app/debug.sh on       # включить (сохраняется после перезагрузки)
~/zorcam-nvr/app/debug.sh status   # что сейчас включено
~/zorcam-nvr/app/debug.sh save     # собрать журналы и состояние системы в ~/zorcam-nvr-debug-<дата>.tar.gz
~/zorcam-nvr/app/debug.sh off      # вернуть обычный режим
```

`on` добавляет:
- монитор (`zorcam-nvr-debug-monitor`): раз в 30 с пишет в журнал состояние питания (`throttled`), температуру, частоту процессора, нагрузку, свободную память, нагрузку на диск (SD-карту), память каждого сервиса Zorcam и процессы, зависшие на диске; смотреть — `journalctl -t zorcam-nvr-debug -f`;
- журнал на диске (до 200 МБ): строки перед зависанием или жёсткой перезагрузкой сохраняются (`journalctl -b -1`);
- предупреждения ядра о процессах, зависших на диске, через 30 с вместо 120 с;
- в Zorcam: каждый запрос к галерее с кодом и временем ответа, статистику детектора раз в минуту и медленные записи на SD-карту, предупреждения ffmpeg, подробный журнал go2rtc.

Чтобы понять, что говорят журналы, запустите диагностику. Она читает журналы (и строки монитора, если отладка была включена) и сообщает о просадках напряжения, троттлинге процессора, ошибках и зависаниях SD-карты, некорректных выключениях, нехватке памяти, перезапусках сервисов и ошибках камеры — с советом по каждому пункту и наиболее вероятной причиной (вывод на английском):

```bash
python3 ~/zorcam-nvr/app/diagnose.py                              # эта Pi, журналы за 7 дней (--days N)
python3 ~/zorcam-nvr/app/diagnose.py ~/zorcam-nvr-debug-<дата>.tar.gz  # архив, собранный save
```

Повторите проблему (после зависания перезагрузите Pi), выполните `save` и пришлите архив. Паролей в нём нет: `secrets.env` не включается, пароли в адресах замаскированы. `off` убирает всё, что добавил `on`, перезапускает сервисы без отладки и снова держит журнал только в памяти (сохранённые на диске журналы удаляются, архивы `~/zorcam-nvr-debug-*.tar.gz` остаются). Отладка пишет на SD-карту больше, поэтому выключайте её, когда причина найдена.

## Удаление

```bash
cd ~ && ~/zorcam-nvr/app/uninstall.sh
```

Запускайте из домашней папки (`cd ~`): терминал не может оставаться в `~/zorcam-nvr`, после того как скрипт её удалит.

Скрипт показывает, что нашёл, и спрашивает перед каждой частью:
1. сервисы (`zorcam-nvr-capture`, `zorcam-nvr-gallery`, `zorcam-nvr-go2rtc` и слежение за настройками), каталоги программы `/opt/zorcam-nvr/capture`, `/opt/zorcam-nvr/gallery`, `/opt/zorcam-nvr/go2rtc`, `/usr/local/bin/go2rtc`, временные файлы в `/dev/shm`, правила ufw для порта 8555;
2. записи в `/var/lib/zorcam-nvr/recordings` — восстановить их будет нельзя;
3. настройки в `/var/lib/zorcam-nvr/config`: `zorcam.conf`, камеры и их пароли, пользователи, их языки и ключи push;
4. клон репозитория `~/zorcam-nvr`.

Если удалены и записи, и настройки, удаляются и `/var/lib/zorcam-nvr`, и пользователь `zorcam-nvr`.

SSH-ключ для GitHub `~/.ssh/zorcam_deploy` (шаг 1 установки) остаётся, поэтому репозиторий можно сразу склонировать снова.

Всё, на что вы ответили «нет», остаётся — например, можно переустановить Zorcam, сохранив записи и настройки. `uninstall.sh --yes` удаляет всё без вопросов. Пакеты (`ffmpeg`, `python3-pil`, `python3-cryptography`, `curl`) остаются. На iPhone удалите иконку Zorcam с экрана «Домой».
